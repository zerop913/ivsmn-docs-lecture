# Методы, классы и объекты: как устроить программу

Программа становится сложнее: нужно посчитать стоимость нескольких заказов, хранить их названия и менять статус каждого. Если писать всё в `main` и заводить отдельные переменные для каждого заказа, код быстро станет трудно читать и изменять.

Разберём два инструмента для организации программы: **методы** позволяют выделить действие, а **объекты** — объединить данные и действия, относящиеся к одной сущности.

После лекции вы сможете написать и вызвать метод с параметрами и результатом, создать класс и несколько объектов, объяснить конструктор и изменение состояния объекта.

## 1. Зачем выделять метод

Допустим, стоимость заказа зависит от цены одной позиции и количества. В одном месте мы считаем стоимость двух тетрадей, в другом — четырёх:

```java
int firstTotal = 120 * 2;
int secondTotal = 120 * 4;
```

Формула повторяется. Выделим её в метод. Ниже — **полная программа**, её можно сохранить в `Main.java` и запустить:

```java
public class Main {
    public static int calculateTotal(int price, int quantity) {
        int total = price * quantity;
        return total;
    }

    public static void main(String[] args) {
        int firstTotal = calculateTotal(120, 2);
        int secondTotal = calculateTotal(120, 4);

        System.out.println(firstTotal);  // 240
        System.out.println(secondTotal); // 480
    }
}
```

Метод `calculateTotal` получает данные, выполняет вычисление и возвращает результат. Описание метода находится в классе, но само по себе ещё не запускает вычисление: оно выполняется при **вызове**.

Разберём строку `int firstTotal = calculateTotal(120, 2);`:

1. Вызов передаёт значения `120` и `2` в метод.
2. Параметры метода получают эти значения: `price = 120`, `quantity = 2`.
3. Внутри метода вычисляется `total = 240`.
4. `return total` завершает метод и возвращает `240` в место вызова.
5. Полученное значение сохраняется в `firstTotal`; выполнение `main` продолжается.

`price` и `quantity` в объявлении — **параметры**, а `120` и `2` при вызове — **аргументы**. Слово `static` здесь позволяет вызвать метод из `main` без создания объекта. Позже увидим методы, которые работают с конкретным объектом.

### Тип результата и `return`

Перед названием `calculateTotal` указан `int`: метод возвращает целое число. Значение после `return` должно подходить этому типу.

```java
int total = calculateTotal(100, 3);
System.out.println(total + 50); // 350
```

Результат можно сохранить, использовать в вычислении или передать другому методу. Вывод на экран и возврат результата — разные действия:

```java
System.out.println(total); // показывает значение в консоли
return total;              // возвращает значение вызывающему коду
```

Вывод сам по себе не передаёт результат в переменную вызывающей программы. После выполнения `return` метод заканчивает работу.

### Метод без возвращаемого значения

Не каждый метод должен отдавать результат. Метод с `void` может, например, вывести сообщение:

```java
public static void printGreeting(String name) {
    System.out.println("Здравствуйте, " + name + "!");
}
```

Разместите метод внутри класса `Main`, рядом с `main`, и вызовите из `main`: `printGreeting("Анна");`. Метод выполнит действие, но записать его результат в переменную нельзя: он не возвращает значение.

**Попробуйте:** измените первый пример так, чтобы программа рассчитала заказ из трёх товаров по 80 рублей. Какое значение вернётся? Проверьте запуском.

## 2. Где существует переменная

Параметры и локальные переменные доступны в пределах своей области видимости. В примере `total`, созданная внутри `calculateTotal`, недоступна напрямую в `main`. Результат попадает в `main` через `return`.

При передаче примитивного значения метод получает его копию:

```java
public static int addBonus(int points) {
    points = points + 5;
    return points;
}

public static void main(String[] args) {
    int points = 10;
    int result = addBonus(points);
    System.out.println(points); // 10
    System.out.println(result); // 15
}
```

`points` в `main` и параметр `points` метода — разные переменные, хотя их имена совпадают. Изменение параметра не меняет переменную в `main`. Чтобы сохранить результат обратно, можно написать `points = addBonus(points);`.

> Эти два метода входят в класс `Main`. Не размещайте один метод внутри другого: в Java методы объявляются внутри класса.

## 3. От отдельных переменных к классу

Теперь хотим хранить не только итоговую стоимость, но и название каждого заказа, его цену и количество:

```java
String firstTitle = "Тетрадь";
int firstPrice = 120;
int firstQuantity = 2;

String secondTitle = "Ручка";
int secondPrice = 50;
int secondQuantity = 4;
```

При добавлении заказов переменных становится всё больше; легко перепутать, какая цена к чему относится. Создадим собственный тип `Order`: каждый объект этого типа будет хранить данные одного заказа.

Создайте два файла в одной папке. Первый — `Order.java`:

```java
public class Order {
    private String title;
    private int price;
    private int quantity;

    public Order(String title, int price, int quantity) {
        this.title = title;
        this.price = price;
        this.quantity = quantity;
    }

    public int calculateTotal() {
        return price * quantity;
    }

    public void printInfo() {
        System.out.println(title + ": " + quantity + " шт.");
        System.out.println("Стоимость: " + calculateTotal() + " руб.");
    }
}
```

Второй файл — `OrderDemo.java`:

```java
public class OrderDemo {
    public static void main(String[] args) {
        Order first = new Order("Тетрадь", 120, 2);
        Order second = new Order("Ручка", 50, 4);

        first.printInfo();
        second.printInfo();
    }
}
```

Запустите `OrderDemo` в среде разработки. В терминале из общей папки выполните `javac Order.java OrderDemo.java`, затем `java OrderDemo`. Вывод:

```text
Тетрадь: 2 шт.
Стоимость: 240 руб.
Ручка: 4 шт.
Стоимость: 200 руб.
```

### Что здесь произошло

- `Order` — **класс**, описание типа: какие данные есть у заказа и какие действия он умеет выполнять.
- `first` и `second` ссылаются на два разных **объекта** класса `Order`. Каждый объект хранит собственные значения полей.
- `title`, `price`, `quantity` — **поля**, то есть данные объекта.
- `calculateTotal()` и `printInfo()` — **методы объекта**. При вызове `first.printInfo()` используются поля первого заказа; при вызове `second.printInfo()` — второго.
- `new Order(...)` создаёт объект и вызывает конструктор, чтобы задать его начальное состояние.

Методы объекта в примере не помечены `static`: мы вызываем их через конкретный объект. А `main` — статический метод: запуск программы начинается с него, ещё до создания `first` и `second`.

## 4. Конструктор и `this`

Взглянем на часть класса ещё раз:

```java
public Order(String title, int price, int quantity) {
    this.title = title;
    this.price = price;
    this.quantity = quantity;
}
```

Конструктор вызывается при создании объекта. Его имя совпадает с именем класса, а тип результата, даже `void`, не указывается.

В выражении `this.title = title;` слева находится поле создаваемого объекта, справа — параметр конструктора. `this` обозначает текущий объект. Когда выполняется `new Order("Тетрадь", 120, 2)`, значения передаются в параметры и сохраняются в поля нового заказа.

**Проверьте себя:** чему будет равна стоимость после создания `new Order("Блокнот", 90, 3)`? Как изменится вывод, если количество будет `1`?

## 5. Состояние объекта и методы

Пусть количество в заказе можно изменить. Добавим в класс `Order` метод:

```java
public void changeQuantity(int newQuantity) {
    if (newQuantity > 0) {
        quantity = newQuantity;
    } else {
        System.out.println("Количество должно быть больше нуля");
    }
}
```

Теперь в `main` после создания заказов можно вызвать:

```java
first.changeQuantity(5);
first.printInfo();  // Тетрадь: 5 шт.; стоимость 600 руб.
second.printInfo(); // Ручка по-прежнему: 4 шт.; стоимость 200 руб.
```

Метод меняет поле **того объекта, через который вызван**. `first` и `second` — разные заказы, поэтому изменение одного не меняет второй.

Проверка в методе не позволяет установить нулевое или отрицательное количество через `changeQuantity`. Но наш конструктор пока принимает любое значение. Чтобы защитить правило для всех создаваемых заказов, в конструктор тоже потребуется добавить проверку. Одного закрытого поля недостаточно, если начальные данные не проверяются.

## 6. Зачем `private`

Поля `Order` объявлены `private`. Поэтому код другого класса не может напрямую написать `first.quantity = -10;`. Изменение проходит через доступный метод, где можно проверить данные.

Это пример **инкапсуляции**: объект управляет своим внутренним состоянием и предоставляет способы работы с ним. Не обязательно создавать публичный метод изменения для каждого поля: сначала нужно решить, какие действия действительно нужны программе.

Если другому коду нужно только прочитать количество, можно добавить метод:

```java
public int getQuantity() {
    return quantity;
}
```

Вызов `first.getQuantity()` вернёт количество, но сам по себе его не изменит.

## 7. Две переменные и один объект

Создание двух объектов и присваивание существующей ссылки — разные операции:

```java
Order first = new Order("Тетрадь", 120, 2);
Order another = first;

another.changeQuantity(5);
first.printInfo(); // количество тоже 5
```

Здесь `new` выполнился один раз: обе переменные ссылаются на **один и тот же объект**. Поэтому изменение через `another` видно и через `first`.

Java всегда передаёт аргументы по значению. Для объекта значением переменной является ссылка: при вызове метода копируется ссылка, и через неё метод может изменить тот же объект. Это отличается от создания новой независимой копии объекта.

## 8. Частые ошибки и как их проверить

| Ситуация | Что происходит | Что проверить |
|---|---|---|
| Метод должен вернуть `int`, но не возвращает результат | Ошибка компиляции, если есть путь выполнения без результата | Возвращается ли значение подходящего типа на каждом пути? |
| Метод выводит число, но его пытаются использовать в вычислении | `void` не даёт результата для выражения | Нужен ли `return` вместо одного только вывода? |
| Вызван `first.printInfo()`, но объект не создан | Обращение по `null` вызовет исключение при выполнении | Какая ссылка хранится в переменной перед вызовом? |
| Второй заказ изменился после присваивания `second = first` | Обе переменные ссылаются на один объект | Сколько раз был вызван `new`? |
| Из другого класса обращаются к `private`-полю | Ошибка доступа при компиляции | Какое действие или чтение должен предоставлять сам класс? |

При проверке меняйте входные данные. Для количества заказа полезны обычное положительное значение, граница `1`, ноль и отрицательное число. Проверяйте и создание объекта, и последующее изменение — это разные пути попадания данных в программу.
